# Adding, retiring and removing a profile

A profile is one file, `src/profiles/<id>.ts`, that exports `profile: Profile` (see `src/profiles/types.ts`), plus
one line in the registry and one pinned-vectors file. Tests fail until all three agree.

## When a new devnet changes the rules

Never edit the profile of a devnet that still runs. Add a new one next to it.

```sh
yarn new-profile ethrex-hegota-devnet-2 --from ethrex-hegota-devnet --supersede
```

This copies the file, registers it, and marks the old profile `legacy` with `supersededBy`. The old profile stays
fully usable: code that names it explicitly keeps working.

Then edit `src/profiles/ethrex-hegota-devnet-2.ts`:

| What changed on the devnet | Edit |
|---|---|
| Field order or layout of the payload | `envelope` (a list of field names; `fees` is the nested list, `maxPriorityFeePerGas` / `maxFeePerGas` / `maxFeePerBlobGas` the flat items) |
| A frame mode was added, renamed or renumbered | `frameModes` |
| An opcode byte or stack order changed, or a new opcode appeared | `opcodes` (set `verified: "spec"` until a test or workshop exercises it on the devnet) |
| A parameter index changed | `params` |
| Predeploys moved | `predeploys` |
| Bytecode must avoid newer EVM opcodes | `yul.evmVersion` |
| A new payload field that no `EnvelopeField` covers | add the field to `EnvelopeField` in `types.ts` and to `encodeField` / `decodeTx` in `src/tx/codec.ts` |

Then:

```sh
yarn pin-vectors ethrex-hegota-devnet-2   # writes test/vectors/<id>.ts from the sample transactions
yarn build:yul                            # compiles the shipped Yul contracts for the new profile
yarn verify
```

Review the pinned vectors against the client (or another implementation) before committing: they are what a
future change is compared with. For the first two profiles they were checked byte for byte against the codecs the
two workshops used before this library existed.

## Retiring

Set `status: "legacy"` and `supersededBy` on the old profile (`--supersede` does this). Nothing else changes. The
profile still encodes the same bytes, and its prebuilt Yul stays.

## Removing

Only when nothing can still use that devnet's rules:

```sh
yarn remove-profile <id>
yarn build:yul && yarn verify
```

It deletes the profile file, its vectors and its registry entry, and refuses while another profile is
`supersededBy` it. `yarn build:yul` drops the generated bytecode.

## The rules that keep this safe

- A profile is frozen once a devnet depends on it. The pinned vectors enforce it.
- Nothing has a default profile. Every function takes one as an argument.
- The registry test fails if a profile file is not registered, a registered profile has no vectors, or a
  generated bytecode entry belongs to a profile that no longer exists.
